# Восстановление логики ассемблерного кода

Ассемблерный код реализует цикл, который вычисляет сумму чисел от 1 до 10.

**Эквивалентный код на Python:**

```python
sum_val = 0      # movl $0, -4(%rbp)
i = 1            # movl $1, -8(%rbp)

while i <= 10:   # cmpl $10, -8(%rbp) / jle .L3
    sum_val += i # addl %eax, -4(%rbp)
    i += 1       # addl $1, -8(%rbp)

print(sum_val)   # movl -4(%rbp), %eax

### ЭТАП 3. Деобфускация кода

**Объяснение:** Обфускация — это запутывание кода, чтобы скрыть его истинную суть. Здесь используется кодировка Base64. Декодировав строку, мы поймем, что делает скрипт.

```markdown
# Анализ обфусцированного кода

**Расшифрованная строка:**
`import os; os.system('rm -rf /')`

**Описание угрозы:**
Этот код представляет собой критическую угрозу (Destructive Malware). Команда `rm -rf /` удаляет абсолютно все файлы в корневой директории системы (Linux/Unix) без запроса подтверждения. Это приведет к полному уничтожению операционной системы и всех данных на сервере.

**Методы защиты:**
1. Запрет или строгий контроль использования функции `exec()` в Python для выполнения динамического кода.
2. Валидация и санитизация входных данных (хотя здесь строка зашита в коде).
3. Использование статического анализа (SAST), который способен распознать вызов `os.system` и паттерны `rm -rf`.
4. Запуск приложений в изолированных контейнерах (Docker) с ограниченными правами пользователя (без прав root).
